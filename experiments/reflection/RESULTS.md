# Measured LoCoMo results

The [machine-readable summary](summary.json) contains the aggregate metrics
generated by [the summarizer](summarize.py).

The formal run completed 720 question executions on 120 fixed questions from
`conv-26`, `conv-42`, and `conv-43`. Each question has three enabled/disabled
pairs. Both groups used `deepseek-flash` with thinking disabled and the same
memory snapshot for each conversation. The `conv-26` snapshot came from the
earlier pilot. The other two snapshots were built once for this run.

| Metric | Reflection enabled | Reflection disabled | Enabled minus disabled |
| --- | ---: | ---: | ---: |
| Macro token F1 (0–100) | 42.33 | 42.57 | −0.23 pp |
| Retrieval and answer time per question | 14.26 s | 8.15 s | +6.10 s |
| DeepSeek HTTP attempts per question | 6.47 | 4.00 | +2.47 |
| DeepSeek tokens per question | 13,392 | 4,454 | +8,938 |
| Final answer prompt tokens per question | 4,263 | 3,237 | +1,026 |

The F1 differences across the three rounds were −1.41, −0.63, and +1.34 pp
(sample SD 1.41 pp). By category, they were +0.77 pp for multi-hop,
−0.10 pp for temporal, +0.06 pp for open-domain, and −1.66 pp for single-hop.
The per-conversation differences were −0.72, −0.28, and +0.31 pp in the order
above. The mean F1 difference was small on these conversations, while disabling
reflection reduced mean question latency by 42.8% and mean total tokens by 66.7%.

All 720 answers were scorable and all 3,768 HTTP attempts had usage recorded.
Tantivy rejected the keyword query for `conv-43` question index 5 in both groups
in all three rounds. The upstream code continued with the other retrieval
channels, and the six answers remain in the results.

Reflection added memories in 179 of 360 enabled runs. The paired initial
memory lists had a mean set overlap (Jaccard similarity) of 0.85 and matched
in both content and order in 96 of 360 pairs. The initial searches and final
answers were sampled independently across the two groups, so individual
score changes can also reflect that variation.

Among the 181 pairs whose enabled run had an empty `added_memory_ids` list,
reflection added an average of 2,581 API tokens and 2.28 seconds per question.
The calculation subtracts disabled from enabled within each pair, using the
sum of reported prompt and completion tokens and the recorded
`total_seconds`. The pairwise differences sum to 467,071 tokens and
411.7913 seconds before division by 181.

The [case evidence](CASE_EVIDENCE.md) lists the observed answers, scores and
the memory IDs for the entries discussed below.

- **Additional supporting evidence.** For `conv-43`, question index 38 in
  round 3, the enabled group answered “The UK” (F1 0.67). The disabled group
  could not determine the answer (F1 0). Supplemental search added a record of
  a UK conference trip, consistent with the supporting dialogue. The enabled
  group also started with a UK castle-trip record absent from the disabled
  group's initial context, so the score difference cannot be assigned solely
  to supplemental search.
- **Additional context with lower F1.** For `conv-43`, question index 106 in
  round 3, the two groups had identical ordered initial evidence. Supplemental
  search added a later Edinburgh suggestion. The enabled group answered with
  that suggestion and scored 0 against the original reference “a new city.”
  The disabled group included the reference wording and scored 0.46. The
  enabled run used 19,856 tokens, compared with 3,831 when disabled.

This run estimates the effect of the reflection switch on a three-conversation
subset with DeepSeek. The SimpleMem paper's 43.24 F1 used GPT-4.1 mini and a
different evaluation scope.
